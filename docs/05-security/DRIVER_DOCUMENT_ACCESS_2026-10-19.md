# Driver licence access - 19 October 2026

**Deployed and verified.** All four current driver licence objects are marked private and owner-bound, their permanent tokens are revoked, and their driver records now store object paths. Direct Firebase, old-token and anonymous GCS requests are denied; all four historical previous-project source links also returned 403. All four files were preserved. Both deployed callables return HTTP 401 / UNAUTHENTICATED without login, and the live Admin HTML references the newly built bundle. Authorized role/owner scenarios were verified with isolated emulators, not real customer credentials.

The Admin driver-details view and the driver's own profile now request the licence through `getDriverDocument`; neither renders the stored download URL. The callable checks Firebase authentication, current account revocation/disabled state, profile suspension, and either the protected Admin role/claim or the matching driver account.

The client supplies a driver ID, not a file path. The server resolves the current `drivers/{id}.driverInformation.license` reference and requires an operator/server-set matching file-owner marker. Copying another driver's reference into a profile does not grant access. Previews return bounded image/PDF bytes with no-store response headers; browser object URLs expire after five minutes. This is a UI cleanup interval, not revocation of a saved/downloaded copy.

`uploadDriverDocument` stores new licence uploads under the authenticated account's licence folder with a protected owner marker and no permanent download token. The dormant registration form uses this endpoint; registration and driver-list routes remain disabled. Allowed uploads are JPG/PNG up to 8 MB, with file-signature checks. The shared Storage policy denies direct reads and client changes to marked files, including metadata removal.

Existing-record protection uses the restricted local `secure-driver-documents-2026-10-19.cjs` operator script. It inventories all driver records, checks for conflicting references/owner markers, marks each current-bucket licence private, revokes permanent tokens, and replaces the driver-record bearer URL with the object path. Files are preserved. Historical links from the previous project are recognized only to resolve an owner-marked current-bucket object; the preview never fetches from the old project.

Validation: frontend production build, 22 shared access/security tests and 14 erasure/retention integration tests passed. New tests cover Admin/owner access, unrelated/food-staff denial, suspension, revoked authentication, removed Admin role, forged document references, invalid content, token-free uploads, protected-object read/write denial, and preserved public root-media reads.
